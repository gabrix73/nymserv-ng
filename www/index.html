What is a Nymserver?

A nymserver (pseudonym server) is a cryptographic email relay that provides individuals with a persistent, bi-directional anonymous identity on the global Internet:

  • Permanent public address: your pseudonym takes the form <alias>@nymserv-ng.virebent.art.
  • Two-way clearnet bridging: you can send emails to any standard mailbox worldwide, and any clearnet sender can reply back to your alias.
  • Zero knowledge of physical identity: unlike commercial email or webmail providers, the nymserver never knows who you are, where you live, or what your IP address is.
  • Cryptographic onion routing: when incoming mail arrives for your alias, the nymserver encrypts the payload with your public key and injects it into the anonymous mix network (YAMN / Reply-Blocks) toward your real mailbox. The server holds only opaque routing tokens, never your true location.

The Service: nymserv-ng

nymserv-ng is a next-generation pseudonym engine engineered from the ground up in pure Rust. It is built specifically for the YAMN (Yet Another Mix Network) anonymous remailer infrastructure, emphasizing strict memory isolation, high concurrency, and defense-in-depth data protection.

The service operates in Dual-Stack mode, bridging historical anonymity conventions with modern post-quantum cryptography:

  • 1. Legacy Channel (OpenPGP / GnuPG): Provides exact bit-level compatibility with classic crooks/ghionym (nymserver.pl) standards. Existing remailer scripts, GnuPG setups, and Mixmaster/YAMN clients can create aliases and operate seamlessly with zero client modifications.

Modern Channel (Post-Quantum NG & pqpg): Overcomes the structural risks of legacy OpenPGP (lack of Perfect Forward Secrecy, key staticity, and vulnerability to Harvest Now, Decrypt Later quantum adversaries). Built upon the official NIST FIPS 203 ML-KEM-768 standard combined with ephemeral X25519 key exchange, AEAD ChaCha20-Poly1305 authenticated encryption, and Ed25519 signatures. Supported by the standalone, pure-Rust CLI client pqpg (Post-Quantum Privacy Guard) with terminal QR code capabilities for air-gapped environments.

Data Custody & Security Architecture

The foundational threat model of 2 novembre assumes that the host server may face unauthorized inspection, network eavesdropping, legal compulsion, or physical seizure (cold-boot extraction). Our security architecture is designed so that seizure reveals nothing useful about our users:

1. Zero-Knowledge Identity Model

The server holds no personal records, phone numbers, payment metadata, or access logs. Pseudonym registration and configuration requests arrive exclusively through multi-hop anonymous remailers. The server has no technical capability to tie an alias to an individual or an origin network node.

2. In-Memory Encryption on Ingestion (+cryptrecv)

When clearnet emails arrive at the Local Delivery Agent (nymserv-lda), they are held exclusively in volatile RAM. Before any storage or queue processing occurs, the message body is encrypted with the alias's public key (OpenPGP or ML-KEM/ChaCha20-Poly1305). No unencrypted user correspondence ever touches persistent disk storage.

3. Volatile Memory Hygiene (mlock & zeroize)

To eliminate page-swapping leaks to NVMe/SSD swap partitions, sensitive memory buffers are pinned in RAM using the Linux kernel mlock syscall. Upon completion of cryptographic transformations, memory regions holding plaintext headers, decrypted commands, or session keys are forcefully overwritten with zeroes using the zeroize compiler-enforced primitive.

4. Forward Secrecy & Quantum Harvest Resistance

In the modern channel, every transmission utilizes an ephemeral post-quantum key encapsulation mechanism. Even if the server's long-term identity keys were compromised or seized in the future, past captured traffic cannot be retroactively decrypted (immune to Harvest Now, Decrypt Later state surveillance).

5. Opaque Onion Reply-Blocks (SURB)

The delivery addresses stored in the database are not email addresses, but pre-encrypted multi-hop reply blocks. The first layer is encrypted with the public key of the initial YAMN mix node. The nymserver is cryptographically blind to the number of intermediate hops and the final recipient address.

6. Embedded ACID Engine & Attack Surface Elimination

nymserv-ng does not run external SQL databases (no MySQL, MariaDB, or PostgreSQL). Storage is handled in-process by redb, a crash-safe, embedded ACID key-value store in pure Rust. There are zero listening network ports, eliminating remote database exploitation vectors.

7. Zero Web Telemetry & Hardened Minimal Delivery

The web presence is strictly plain text and lightweight HTML. Nginx operates with access_log off (zero visitor IP logging), no cookies, no tracking scripts, and a strict Content Security Policy (default-src 'none'). The site functions natively in Lynx, w3m, Tor Browser, and over the Gemini protocol.
