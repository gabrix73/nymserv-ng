The Post-Quantum channel of nymserv-ng eliminates the systemic cryptographic obsolescence of classical public key algorithms (RSA and elliptic curves) against cryptanalytic quantum computers (Shor's algorithm and passive Harvest Now, Decrypt Later surveillance).

Why Post-Quantum in Plain English?
Messages encrypted with legacy RSA/PGP can be recorded by mass-surveillance programs today and decrypted a few years from now when quantum machines mature.
The Post-Quantum channel protects your pseudonym identities using the standardized NIST FIPS 203 (ML-KEM-768 / Kyber) lattice algorithm, guaranteeing that your communications remain unconditionally unbreakable into the future.

2. Step-by-Step Guide for Beginners: Creating a Post-Quantum Alias

Step 1: Generate your ML-KEM-768 keypair

Use the official nymserv-ctl command-line utility (available in GitHub releases) or any FIPS 203 compatible library (Rust ml-kem, liboqs, or Python): 

# Generate PQ keypair with nymserv-ctl
nymserv-ctl gen-keys --pq-only --out-dir ~/.nymserv-keys

This generates two files:

  • user-pq-pubkey.bin (1,184-byte public encapsulation key).
  • user-pq-secret.bin (Private decapsulation key, keep strictly confidential).

Step 2: Prepare the PQ registration configuration

Create a text file config-pq.txt including your public key in hex format and your Reply-Block: 

Config:
From: youralias-pq@nymserv-ng.virebent.art
PQ-Algorithm: ML-KEM-768
Public-Key-Hex:
[PASTE HERE THE HEXADECIMAL STRING OF user-pq-pubkey.bin]
Reply-Block:
::
Anon-To: your_real_email@secure-provider.org

Nym-Commands: +cryptrecv +pqsend

Step 3: Encapsulate and Encrypt for the Server

Encapsulate a 32-byte shared symmetric key using the server's public key (nymserver-pq-pubkey.bin) and encrypt the payload using ChaCha20-Poly1305: 

nymserv-ctl pq-encrypt --recipient-key nymserver-pq-pubkey.bin config-pq.txt > config-pq.bin.asc

Step 4: Dispatch the registration to config@

Send the resulting payload to:

config@nymserv-ng.virebent.art

The server decapsulates the shared secret, inserts your pseudonym into the embedded ACID redb engine, and dispatches a post-quantum confirmation message to your Reply-Block.

3. Receiving Post-Quantum Messages (Inbound)

When anyone writes to youralias-pq@nymserv-ng.virebent.art:

  1. The server encapsulates an ephemeral 32-byte secret against your ML-KEM-768 public key.
  2. The message body is encrypted with ChaCha20-Poly1305.
  3. The post-quantum ciphertext packet is dispatched to your Reply-Block.
  4. On your machine, decapsulate the shared secret using user-pq-secret.bin and decrypt the payload instantly.

4. Sending Outbound Mail via Post-Quantum Channel (send@)

To send clearnet email displaying your PQ alias as the sender:

  1. Sign the message with your Ed25519 or ML-DSA private key.
  2. Encapsulate and encrypt the payload to the server's ML-KEM public key.
  3. Send the encrypted message to send@nymserv-ng.virebent.art.
  4. The server verifies the signature, appends the anonymous disclaimer, and delivers the message to the destination address.
