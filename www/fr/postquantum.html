Le canal Post-Quantique de nymserv-ng immunise les identités pseudonymes contre les attaques futures par ordinateurs quantiques (algorithme de Shor et interceptions massives Harvest Now, Decrypt Later).

Pourquoi le Post-Quantique pour Débutants ?
Les e-mails chiffrés aujourd'hui avec RSA/PGP peuvent être interceptés et stockés pour être déchiffrés dans quelques années par des calculateurs quantiques.
Le canal Post-Quantique protège vos pseudonymes avec le standard officiel NIST FIPS 203 (ML-KEM-768 / Kyber), assurant une confidentialité inviolable dans le temps.

1. Comment Obtenir la Clé Publique Post-Quantique du Serveur

Téléchargez la clé publique d'encapsulation ML-KEM-768 via le web ou demandez-la par e-mail :

  • Via le Web : => Télécharger nymserver-pq-pubkey.bin (1 184 octets bruts)
  • Via E-mail : Envoyez un courriel à key@nymserv-ng.virebent.art. Le moteur automatique répondra avec la clé OpenPGP et la clé ML-KEM-768 encodée en hexadécimal.
  • Empreinte SHA256 :
    74c8ebca73fa8e7b9dd6329fc2f99580ef14cebb80ee7b3547fb0be550b7194f

2. Guide Pas à Pas pour Débutants : Création de votre Alias Post-Quantique

Étape 1 : Générez votre paire de clés ML-KEM-768

Utilisez l'utilitaire en ligne de commande nymserv-ctl (disponible dans les releases GitHub) ou une bibliothèque FIPS 203 : 

# Génération de la paire de clés avec nymserv-ctl
nymserv-ctl gen-keys --pq-only --out-dir ~/.nymserv-keys

Cela produit deux fichiers :

  • user-pq-pubkey.bin (Clé publique d'encapsulation de 1 184 octets).
  • user-pq-secret.bin (Clé privée de décapsulation, à garder strictement secrète).

Étape 2 : Préparez le fichier de configuration Config

Rédigez le fichier texte config-pq.txt en insérant votre clé publique en hexadécimal et votre Reply-Block : 

Config:
From: votrealias-pq@nymserv-ng.virebent.art
PQ-Algorithm: ML-KEM-768
Public-Key-Hex:
[COLLEZ ICI LA CHAINE HEXADECIMALE DE user-pq-pubkey.bin]
Reply-Block:
::
Anon-To: votre_vraie_adresse@fournisseur-securise.org

Nym-Commands: +cryptrecv +pqsend

Étape 3 : Encapsulez et Chiffrez pour le Serveur

Encapsulez un secret partagé de 32 octets avec la clé publique du serveur et chiffrez le contenu avec ChaCha20-Poly1305 : 

nymserv-ctl pq-encrypt --recipient-key nymserver-pq-pubkey.bin config-pq.txt > config-pq.bin.asc

Étape 4 : Envoyez la configuration à config@

Envoyez le résultat à :

config@nymserv-ng.virebent.art

Le serveur enregistre l'alias dans la base de données redb et expédie une confirmation post-quantique à votre Reply-Block.

3. Réception de Courriels Post-Quantiques (Entrant)

Lorsque quelqu'un écrit à votrealias-pq@nymserv-ng.virebent.art :

  1. Le serveur génère une clé éphémère ML-KEM-768 encapsulée avec votre clé publique.
  2. Le corps du message est chiffré avec ChaCha20-Poly1305.
  3. Le paquet chiffré est transmis à votre Reply-Block.
  4. Sur votre machine, décapsulez le secret avec user-pq-secret.bin et lisez le message instantanément.

4. Envoi de Courriels Sécurisés (Sortant via send@)

Pour expédier un e-mail avec votre alias PQ en expéditeur :

  1. Signez le message avec votre clé Ed25519 ou ML-DSA.
  2. Encapsulez et chiffrez pour la clé ML-KEM du serveur.
  3. Envoyez le paquet à send@nymserv-ng.virebent.art.
  4. Le serveur valide la signature, applique l'avertissement et achemine le message à destination.
